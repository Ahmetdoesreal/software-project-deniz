Use this as a lookup page. If you see a route, event, command, or GUI action in the code or logs, this tells you which sequence guide explains it.

HTTP Routes

If you see this What it does Read this
GET /health Client checks that the server is alive. Client startup, WebSocket, and policy sync
POST /login Client exchanges login id and password for a session UUID. Client startup, WebSocket, and policy sync
GET /exam/config Client asks for exam duration and whether exam files exist. Client startup, WebSocket, and policy sync
GET /exam/files Client downloads the configured exam zip. Client startup, WebSocket, and policy sync
GET /ws?id=<uuid> Client opens the live WebSocket connection. Client startup, WebSocket, and policy sync, Exam timer and session state
POST /client/artifact Client uploads runtime evidence: replay, process report, incident bundle. Replay, savescreen, and artifacts, Monitoring, incidents, and process actions
POST /exam/submission Client uploads the final submission bundle. Final submission and uploads

WebSocket Events

Event Direction Plain-English meaning Read this
welcome server to client Connection accepted; client can introduce itself. Client startup
client_info client to server Client sends computer name. Client startup
exam_policy server to client Initial monitoring and exam policy. Client startup
policy_update server to client Policy changed while clients are connected. Monitoring and incidents
policy_applied client to server Client confirms policy apply success or failure. Client startup
process_blacklist server to client Legacy/direct blacklist update. Monitoring and incidents
start_exam client to server Student is ready to begin. Exam timer
sync_time server to client Authoritative remaining time and timer state. Exam timer
session_state server to client Full state such as waiting, running, paused, awaiting submission. Exam timer
pause_exam server to client Pause this student. Exam timer
resume_exam server to client Resume this student. Exam timer
finish_exam server to client Open final submission flow. Exam timer, Final submission
exam_end server to client Legacy/direct exam-end signal. Exam timer
savescreen server to client Save recent replay evidence. Replay and savescreen
get_processes server to client Export and upload current process list. Replay and artifacts
incident_report client to server Client reports an incident or evidence status update. Monitoring and incidents
incident_received server to client Server acknowledges the incident update. Monitoring and incidents
client_monitor_event client to server Live monitor telemetry, mainly focused-window status. Monitoring and incidents
process_catch client to server Blacklisted process was detected. Monitoring and incidents
kill_process server to client Server asks client to terminate a PID. Monitoring and incidents
kill_process_result client to server Client reports whether PID termination worked. Monitoring and incidents
ping / echo client to server / server to client Manual connectivity check. Client startup
time server to client Heartbeat-style time broadcast. Exam timer
error both Something was rejected or could not be decoded. Relevant sequence based on context.
